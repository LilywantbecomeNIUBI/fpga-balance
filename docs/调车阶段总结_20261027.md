日期：2026-10-27。硬件结果截止最近一次 18:01 的 M1 短测；本总结整理期间未发电机命令。

## 1. 当前结论

我们已经完成集成系统的传感器启动修复、IMU安装方向确认、左右轮与轮速方向确认、两路电角标定、独立标定入口，以及“普通清故障保留电角标定”的修改和板上验证。

当前主要阻塞：M1在 +0.15 A / +0.20 A 的200 ms电流短测中反复触发编码器速度保护，但用户反馈没有看到轮子转动。日志确实记录到了编码器连续变化；这尚不能独立证明轮胎实际转动，也不能直接判为编码器误报。

## 4. 我们修改了什么

### 4.1 修复集成IMU启动顺序

首次失败过程被捕获：成功读到WHO_AM_I=0x47，写入软复位成功，随后访问INT_STATUS(0x2D)时NACK。单独版与集成版IMU核心文件一致；降低I²C速度、延长复位等待未解决。

有效修改：先完成IMU初始化，再释放ADC/编码器逻辑。外设释放状态被锁存，运行中的IMU故障仍走停机保护，不自动复位电机保护。

**已确认启动顺序修复有效；尚未确认究竟是供电扰动、信号耦合还是接口活动导致原失败。**

### 4.2 固定已经确认的安装配置

FPGA、协议和上位机同步精简：删除IMU轴/符号/重力方向选择，固定Y轴、前倾正、直立−Z；删除两轮前进速度方向选择，固定右M1取反、左M2不反；拒绝不兼容旧参数。

尚未验收的转矩方向选项仍保留。`axis_confirmed`表示IMU姿态与车轮前进轴向已确认，不能解释为两轮纠偏转矩方向已验收。

### 4.3 改成两路分别标定

新增明确命令：opcode9只标M1，opcode10只标M2；拒绝旧opcode5自动下一路接口。支持M2先标，另一轮不作为前置动作，不排队自动切换；失败后显示所选电机自身的状态，避免把M1 COMPLETE误读成M2成功。

### 4.4 普通清故障不再清掉成功电角标定

集成版开启 `PRESERVE_CAL_ON_CLEAR=1`，遥测byte17 bit7声明能力。

| 操作 | 电角标定处理 |
|---|---|
| 普通人工清故障 | 保留已成功的电角零位、方向、完成位；不会自动运行 |
| 点击某一路标定按钮，包括已完成的一路 | 明确重新标该路，先使该路旧完成位失效；另一路保留 |
| 该路重新标定失败 | 不允许继续沿用该路旧完成结果 |
| FPGA复位、逻辑掉电或重新下载 | 两路电角标定清空，需要重标 |
| 只重新电流校零 | 本轮实测保留两路电角完成位 |

参数仍需重新应用，电流/姿态仍需重新校零。本次没有做Flash持久化。历史单独版默认清除行为保持原样。

### 4.5 修复开发过程中的其他问题

- 修正观察模式下被电机故障锁存阻挡姿态准备的问题；驱动模式门禁保留。
- 独立标定候选曾有约−0.174 ns的时序违例；去掉生命周期使能路径中的冗余状态译码后通过。物理故障/急停快速关断没有增加寄存延迟。
- 一次临时操作脚本在clear后立即读取旧故障帧，误判失败并提前stop，未启动电机；已改为等待新的清除回执。该事件属于脚本问题，不是又一次电机硬件故障。

## 6. 保护到底报了什么

### 6.1 最近短测：速度保护，未报过流

故障字组合为 `{measurement_faults, command_faults, core_faults}`。

| 位/数值 | 当前源码含义 | 最近0x489是否包含 |
|---|---|---|
| 0x400 | 编码器速度检查失败 | 是 |
| 0x080 | 核心运行就绪条件失效 | 是，连锁状态 |
| 0x008 | 传感/测量故障链路 | 是，速度故障也进入此链路 |
| 0x001 | 急停/停止锁存 | 是 |
| 0x010 | 相电流过流 | **否** |

最早记录中supervisor的`stop_reason=0x4`表示因电机故障停止；随后上位机按异常策略发送X，`stop_reason`变为0x1。组合码及200 Hz日志不能还原每个内部故障位的逐时钟先后顺序。

当前速度检查有两条：

- 单帧位置变化超过±64 tick。
- 16帧累计位置变化超过±32 tick；20 kHz下16帧约0.8 ms，32 tick换算约146.5 rpm。

当前只知道速度保护位被置位，没有锁存触发时的具体检查分支、原始位置增量和窗口累计值。因此“真实轮速超过146.5 rpm”和“编码器数据异常”尚未区分。慢速串口记录中的峰值低于这一换算值，也不能否定更短窗口触发。

### 6.2 早期M2标定：另有一次相过流

17:00的M2标定记录包含0x010相过流位，随后停止后为0x011。该次串口相电流峰约0.419 A，低于0.50 A门限，但保护走20 kHz链路，遥测约200 Hz，不能据此说过流一定误报。

## 9. 已做的单独版对比及其边界

曾将历史M2成功独立位流与当时集成版e2d525f5…的构建输入逐模块比较，11个模块中10个一致，包括当时的电角标定FSM、电流处理和FOC桥接；主要核心差异是motor_adapter_core中的cal_start登记一拍，约20 ns，未证明它是异常原因。

两者标定Id/Iq、标定PI、位移和电流验收条件基本相同；集成版还同时存在双路保护、IMU、上位机与启动管理等差异。因此“单独版成功”不能推导出集成系统已通过全部验收。

该比较报告针对旧e2d525f5…版本。后续已明确修改motor_safe_drive和motor_commission的生命周期逻辑，**不能把历史的10/11一致描述直接套到当前新版**。

1. **先消除机械运动与编码器数据的矛盾。** 断12V、保留逻辑供电，分别给轮胎/轮毂/转子做可见标记；手动转动时同步记录编码器1/2和画面，核对转动对象、对应通道、方向及累计一圈约16384 tick。此前手动方向试验已通过，此次重点是核对真实机械连接和通电异常条件，不是无目的重复。
2. **补足速度故障快照。** 停机保留触发分支、单帧delta、16帧累计值、编码器原始值和时间戳、选中电机、使能/运行状态。先分析证据，再决定是否存在编码器问题或门限与测试工况不匹配，不直接删除保护。
3. **处理静止电流漂移。** 在无驱动输出条件下记录校零前后、不同等待时长和温度下的均值/峰值。确认偏置稳定性，并核对实际电流增益；重新校零只是暂时准备动作，不是根因修复。
4. **设计可观察的单轮方向试验。** 在机械/编码器一致后，选择合适的电流、有效通电时间和同步记录方式；分别验证M1/M2的Iq正负与车体前进关系。现有协议最短运行配置为100 ms，不能声称已支持任意更短脉冲。
5. **两路纠偏符号确认后再调直立PD。** 可靠支撑、限流和有限时长，检查前倾/后倾时的纠偏方向，再分步调增益；其后才加入速度PI，最后验证落地平衡与长期稳定性。

完成标准：不只是“命令发出”或“故障位没有出现”，而是参数、实际电流/机械响应、保护过程和对应版本都有可追溯证据。
