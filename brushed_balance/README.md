# P30 有刷平衡车独立工程

此文件夹可独立复制使用，不引用原 FOC 工程或系统集成工程的源码路径。目标为 ACG720 / GW5AT-LV138PG484AC1/I0、双 WHEELTEC MG513P30、AT8236 D157B、AB 编码器和 ICM-42688-P。

当前源码已将两台有刷电机的4路控制和4路编码器集中到旧载板M2-23～30，另用21/22共地，接线见[集中M2接线表](docs/M2_WIRING.md)。M2版尚未下载，板上仍是之前分散引脚观察版；新接线必须配套新位流。

此前分散引脚观察版已验证COM10与IMU：身份0x47，约1002.37Hz原始采样，无I2C/CRC错误。电机动力尚未由本工程试转；方向、供电档位、CPR、PI/PD和实车平衡仍未实测。直立和速度外环增益默认0。

观察版提供5Hz只读IMU诊断：WHO_AM_I、错误码、原始六轴和SCL/SDA电平。M2方案有独立遥测标志，上位机拒绝旧分散引脚固件解锁。位流SHA256以`docs/validation.md`最新记录为准。

## 从哪里开始

此Git分支的仓库根目录提供`启动有刷平衡车.cmd`。克隆、独立运行和交接步骤见[Git交接说明](docs/GIT_HANDOFF.md)，已构建位流见[固件说明](firmware/README.md)。

双击 `start.cmd`：

1. 离线演示：打开本工程调参台，不打开串口。
2. 实机控制台：仍需在页面中选择串口、点击连接；不会自动解锁。
3. 构建 M2 接线 GMR 观察版：四路 AT8236 输入和旧 M1 输出均固定低，四路编码器为输入。
4. 构建 M2 接线 GMR 驱动版：具备单轮测试和双轮平衡控制能力。

上位机地址为 `http://127.0.0.1:8878/`。本工程使用独立串口协议，不共用旧的 8874/18866 服务，也不需要 Nano。

```powershell
python tools/test.py
python tools/run.py --demo
python tools/run.py --live
python tools/build.py --profile observe
python tools/build.py --profile drive
```

Python 3.10+；`tools/run.py` 会建立本目录 `.venv` 并从附带 wheel 离线安装 pySerial。仿真需要 Icarus 和 Node.js；构建使用 Gowin V1.9.12.04，其他安装位置可设置 `GOWIN_HOME`。所有构建命令只生成文件，不下载板卡。

## 已实现的控制路径

| 模式 | 控制方式 | 用途 |
| --- | --- | --- |
| 0 | 电机硬关闭，只观察 | 编码器、IMU、串口检查 |
| 1 | 单轮有符号 PWM | 确认轮向与编码器反馈 |
| 2 | 单轮速度 PI，100Hz | 复用之前的电机测速调参流程 |
| 3 | 姿态融合约 1kHz → 直立 PD → 双轮 PWM | 先调直立 |
| 4 | 50Hz 速度 PI → 目标倾角 → 直立 PD → PWM | 直立稳定后调速度 |

平衡模式绕过单轮速度 PI 和它的静止换向等待，允许及时施加正反向纠偏。PWM 沿用旧程序的 10kHz 慢衰减和约 1.1ms 唤醒；零指令、STOP、禁用输出为 `00` 滑行。

单轮模式只使能所选电机，时长 100~5000ms，FPGA 内部到时停机。直立模式持续运行，直到显式停止或故障。编译期 PWM 硬限幅 300‰；页面默认限幅 100‰。测速 PI 的积分限幅随本次 PWM 上限变化，包含抗饱和。

姿态沿用原车安装：Y 俯仰，`-ax/-az` 求倾角、`-gy` 为俯仰角速度，前倾为正，直立约 `az=-8192`。姿态零点需静止约 1024 个样本；电机/编码器方向可分别设置，不能用其中一个代替另一个。

## P30 与编码器

厂商资料同时列有 P30 的 8V、12V 版本。本程序没有自动识别额定电压，接线前看实际电机标签。

`config/motors.json` 提供两种配置，均标记为**理论值、未实测**：

| 配置 | 电机轴编码器 | AB 四倍频后输出轴 CPR |
| --- | --- | --- |
| `p30_gmr`（默认） | 500 ppr | 30 × 500 × 4 = 60000 |
| `p30_hall` | 13 ppr | 30 × 13 × 4 = 1560 |

GMR 与霍尔可以共用标准 AB 解码，但测速比例、PI 增益和边沿频率不同。旧约 1500 计数/圈的实测不能继承到新电机。CPR 已包含减速箱和四倍频，不能再次乘 30 或 4。

测速关系：`rpm = 每10ms计数 × 6000 / 输出轴CPR`。高分辨率 GMR 的 1rpm 对应约 10 计数/10ms。

如果实物为霍尔版，构建与上位机均指定同一配置：

```powershell
python tools/build.py --profile drive --encoder p30_hall
python tools/run.py --live --profile p30_hall
```

实测两轮 CPR 后改 `config/motors.json` 中对应的 `left_cpr`、`right_cpr`，将 `measured` 改为 true，再重新构建并启动配套上位机。固件会回报两路 CPR；上位机拒绝 CPR 不匹配的解锁。

**具体接线差异：**厂家产品说明第 5 页的 GMR 与霍尔 6Pin 线序不同，需按该图核对配套排线；不能凭“都有 6Pin”认定相同。编码器高电平跟随编码器供电，本 FPGA 输入按 3.3V 配置，5V 输出需要电平转换。

## 接线与首次调试

完整表在 `constraints/pins.csv`，全部电机与编码器信号集中到载板M2：

| 功能 | M2 / J_DRV2 | P7 | FPGA |
| --- | --- | --- | --- |
| 共地 | 21 / 22 | 地网 | — |
| 右 A / B | 23 / 24 | 18 / 19 | C15 / B15 |
| 左 IN1 / IN2 | 25 / 26 | 10 / 13 | E14 / C13 |
| 右 IN1 / IN2 | 27 / 28 | 14 / 15 | B13 / D14 |
| 左 A / B | 29 / 30 | 16 / 17 | D15 / C14 |
| IMU SCL / SDA | 原J_IMU1 | 39 / 40 | F19 / F20 |

先移除M2接口原有DRV8323模块及连接。旧M2 EN/PWM/CAL不再是固定低输出，已由新的控制/编码器端口接管；旧M1的8个输出仍固定低。新产物目录后缀`_m2`，不能用旧分散引脚位流替代。详见接线表中的换线顺序及10k下拉负载说明。

首次按以下顺序：

1. 观察固件检查静止数据；手转每个轮子若干整圈，用位置差/圈数测 CPR，正反方向分别检查。标准解码会累计真正的非法跳变，没有旧程序的方向推测补偿。
2. 驱动固件首次运行时两轮架空、机身固定；逐轮 PWM 检查，确认“车辆向前”对应轮向和反馈均正确。每次应用参数均保持停机，目标在解锁时归零，再手动发送。
3. 单轮速度 PI 重新整定。GMR 计数更密，同样 rpm 的计数误差更大，旧霍尔 Kp4096/Ki128 只是历史结果，未作为本工程默认值。
4. 机身在期望直立位置静止，做姿态校零。直立模式速度外环关闭，从零增益、低输出限幅开始；确认前倾时两轮朝能托回重心的方向纠偏，再调 Kp/Kd 和直立微调。
5. 直立稳定后才启用速度外环，目标先 0rpm，速度 Kp/Ki 从 0 开始。

本工程没有相电流、母线电压或温度采样；PWM 限幅不是电流限制。未实现位置环、转向环、轮腿控制或导航。观察/数字仿真通过不等于能让实车立住。

## 停机与记录

FPGA 保留上电/STOP 锁存、显式 CLEAR/ARM、250ms 命令看门狗；直立模式检查 IMU/姿态新鲜度，默认 ±5°允许启动、±35°倾倒停机。AB 非法跳变过多、按配置 CPR 换算的 800rpm 计数门限、输出至少 100‰但持续 500ms 无编码器运动也锁停。这些不是独立的电流/温度保护。

上位机只有在页面持续发送心跳时才续发 FPGA 心跳；页面心跳超过 0.6s 或遥测超过 0.15s 未更新会请求 STOP，关闭/隐藏/失焦同样请求 STOP。复位、故障恢复和重新连接均不会自动解锁。正常单轮到时结束不会清除姿态零点。

实机连接后 `results/时间戳/` 保存 `rx.bin`、`events.jsonl`、`samples.csv` 和已确认的 `config.json`。页面可导入/导出参数 JSON。参数单位和协议见 `docs/protocol.md`；来源见 `docs/sources.md`；离线验证结果见 `docs/validation.md`。
